# 05_output

Run results. Each driver writes a complete set of estimates, diagnostics, and plots here. Nothing in this folder is hand-authored; it is all regenerated from `04_input_files/` plus the chosen model and parameters, so any run can be reproduced by re-knitting the matching driver.

For the meaning of the populations, sub-seasons, and the PE-vs-BSS gate referenced throughout, see the [root README](../README.md).

## Folder structure

```text
05_output/
  <run_date>/                       # YYYYMMDD, set by run_date <- format(Sys.Date(), "%Y%m%d")
    <model>-<run_tag>/              # one subfolder per driver run; run_tag names it
      <output files>
    run_manifest_<timestamp>.txt    # one per orchestrated run, at the <run_date> level
```

`output_dir` is set once in each driver's setup chunk by `bss_output_dir("<model>-", run_config)` (B46), which resolves to `here("05_output", <YYYYMMDD>, "<model>-<run_tag>")`; every write lands under it. The tag is made path-safe, a season token in it must match `season_filter` (or be the span label), and a tag naming a non-empty folder gets `-HHMMSS` appended rather than overwriting it. `run_estimation.R --model both` also writes `cross_check_<timestamp>.csv` at the `<run_date>` level. The `run_tag` comes from `run_config.R` (or is set by `run_rg_sweep.R`) and names the folder, e.g. `pooled-CPUE-run1`, `gear-type-CPUE-model-run2`, or `pooled-CPUE-run5-RG-1.00`. Keep a `run_tag` to letters, digits, `-` and `_`: some historical folders carry spaces and `=` in their names (for example `20260720/gear-type-CPUE-model-gear_resolved_G = TRUE`), which work but have to be quoted in every shell command and path. When `run_tag` is blank the driver appends an `HHMMSS` timestamp instead, so two runs of the same model on the same day land in **different** folders and no longer overwrite each other. Older dated folders stay immutable records of past runs. The orchestrator also writes a `run_manifest_<timestamp>.txt` at the `<run_date>` level (one per orchestrated run). Because the pipeline has grown over time, **older runs legitimately contain fewer or differently named files than recent ones**; that is history, not breakage.

The `<model>` prefix is whatever the driver set, and it has changed across versions. You will see, for example, `pooled-CPUE-model`, `pooled-CPUE` and `gear-type-CPUE-model`. Recent production-driver runs append the `-<run_tag>` suffix described above, so a current folder looks like `pooled-CPUE-run1`; older folders predate the run_tag scheme. The `pooled-CPUE-covariates` prefix belonged to the weather-tide module, removed 2026-09-13 (A29); no code writes it now and no committed folder carries it.

## File naming convention

Most per-population files follow:

```text
<metric>_<population>_<species>_<fate>.{csv,png}
```

- `population` is one of `shore_ring_net_only`, `shore_all_gear`, `private_boat_ring_net_only`, `private_boat_all_gear` (`ring_net_only` is the pot-closure sub-season's internal key; a multi-season run appends `_<season>` to the sub-season).
- `species` is `Dungeness`; `fate` is `Kept`.

So `bss_daily_catch_private_boat_all_gear_Dungeness_Kept.csv` is the daily catch series for the private-boat all-gear component. Port-level and cross-population files (totals, monthly, comparisons, metadata) drop the population tag.

The commercial/charter component has **no** per-population BSS file; it enters the port total as the commercial census over `wes_commercial_tally.xlsx` plus the charter expansion over `charter_trips.xlsx` (`census_daily.csv`, `census_variance.csv` below).

## Why outputs are committed

These results are checked into the repository so a given seasonal estimate and its diagnostics are preserved exactly as produced, without needing to re-run. The trade-off is repository size; this folder is the bulk of it. Per-run R workspaces (`*.RData`) and compiled model caches (`*.rds`) are **not** committed; they are git-ignored because they are machine-local and regenerate on demand (see `.gitignore`). If repository size becomes a problem, the alternative is to stop committing dated runs and keep only the inputs plus a tagged driver, accepting that past estimates would then have to be reproduced rather than read.
