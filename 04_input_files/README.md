# 04_input_files

The raw season data the drivers read. These are the only inputs a local run needs; everything in `05_output/` is regenerated from these input files plus the model and parameter settings. Reads are done with `here("04_input_files", <name>)`, so the files are found regardless of which driver knits or where it sits.

For what the estimate is and how these feed the PE and BSS paths, see the [root README](../README.md).

## The input set (2026-09-10): nine workbooks, seven of them BUILT

All inputs are `.xlsx` workbooks with a single `data` sheet. Every file carries a fishery-season column, dates are stored as ISO `yyyy-mm-dd` text, and every reader goes through `read_input_workbook()` (`03_R_functions/read_input_workbook.R`), which guesses each column's type over the whole column rather than readxl's first 1,000 rows (several columns are blank for a whole early season; see B17 in the change register).

Seven of the nine are DERIVED from the per-season creel workbooks in `raw/` by the builders next to them (`Rscript 04_input_files/build_all_inputs.R` from the repository root runs all six in order; each prints its report and a comparison with the workbook it replaces). A model workbook is therefore never hand-edited: a new season is its workbook in `raw/` plus one script run.

`WBL_boat_counts.xlsx` is read only when `run_config$use_osp_boat_counts = TRUE`. The former per-fishery opener workbooks (`MA2-fishing-dates-2023-2026.xlsx`, `razor-clam-dig-dates-2021-2025.xlsx`) are retired; their content is represented in `fishery_opener_dates.xlsx`.

**`WestportCrabOnlyEffort` (optional, added 2026-08-25; not yet delivered).** A per-day count of boats OSP labelled as crabbing ONLY, alongside the existing all-fishery daily total. When present it feeds a HARD LOWER BOUND on the crabbing fraction `f` (`use_osp_crab_lower`); when absent every f feature is inert and `f` behaves exactly as it does today. Column name configurable via `run_config$osp_crab_only_col`. **What it is and is not:** OSP does not record combo trips, so a boat that crabs AND fishes another fishery is labelled by the other fishery. The count therefore bounds `f` from below and is NOT an estimate of it; the model treats it that way by construction (`f = f_lower + (1 - f_lower) * theta`). Getting the combo share `theta` requires the WPT/WBL egress classification (`boats_crabbing` / `boats_total` in `ingress_egress.xlsx`), ideally on the same days OSP is in port. The reader clamps and reports, rather than silently truncating, any day where the crab-only count exceeds the daily total, since that is a data error rather than a combo effect. Follows the same NS-vs-zero rule as the total: an absent date is non-sampled, an observed 0 is data.

**`boats_crabbing` / `boats_total` in `ingress_egress.xlsx`** (present, currently blank) are the WPT/WBL egress crab-vs-total classification counts on the boat-I/E (WBL) rows. Unlike the OSP crab-only count, a boat that crabs AND fishes something else counts here as CRABBING, which is why this stream identifies `f` directly and the OSP stream cannot.

## What the builders do, and what the 2026-09-10 rebuild changed

- **Interviews** (`build_interview_combined.R`). One row per interview from every season's `Harvest Creel` sheet. The 21 columns of 2026-09-09 keep their names, order, types and cleaning; rebuilt against the previous workbook row by row, the legacy columns differ only where the database was corrected (one trip, two boat types, one completed-trip value of 24 now NA, twenty interview times the pasted export had lost, and the 2022-23 site names now mapped to the current vocabulary). Two things changed for the model: **the 2023-24 gear count is present** (13,629 counts, 0 to 23; it had been read as NA because the 2023-24 sheet heads it "Number Of Gear"), and **`gear_type` carries the 2024-25 gear vocabulary in every season** (`gear_type_raw` keeps the label as recorded). The iForm renamed its gear labels for 2024-25 ("Collapsible trap or ring" -> "Ring Net", "Fishing rod with foldable trap" / "Star trap" -> "Trap (foldable, star)", "Fishing rod with snare" -> "Snare", "Rake, net or hands" -> "Rake or Net"; the 2023-24 workbook's `gear_key` sheet), and the gear-resolved classifier (`prep_bss_crab_gear.R`, `gear_share_bootstrap.R`) matches "ring net", "trap|star", "snare", "pot" by regex, so on the old labels a ring net was classed as a trap. 2024-25 and 2025-26 rows are unchanged by the map (five lower-case "pot" rows aside).

  **There was no ring-net option before 2024-25** (asked and answered 2026-09-11). The 2022-23 and 2023-24 forms offered `Collapsible trap or ring`, `Pot`, `Slip ring pot`, `Fishing rod with foldable trap`, `Star trap`, `Fishing rod with snare`, `Rake, net or hands`, `Handline`, `Other`, `Unknown`; `Ring Net` first appears in 2024-25. So the map follows the `gear_key` crosswalk rather than choosing between two options that existed. The caveat to keep: the old label is ONE option where the current form has two, and the old trap option was rod-mounted (`Fishing rod with foldable trap`), so a hand-held foldable trap had nowhere else to go. Across the vocabulary change the combined ring-plus-trap share of gear tokens is stable (43% of 2023-24 tokens, 45% of 2024-25) while its internal split moves from 66/34 ring:trap to 47/53 -- a moved boundary rather than a change in gear use. This reaches a gear-resolved fit of 2022-24 only; the pooled model does not split by gear and the gear-resolved 2024-25 cross-check is on the new vocabulary (CHANGE_REGISTER D20).
- **Effort counts** (`build_effort_combined.R`). Every count column of every protocol; `boat_trailer_count` is the 2022-24 "Truck/Boat Trailer Count" and the 2024-25+ "Boat Trailer Count" (at Westport Boat Launch the separate 2024-25+ vehicle count is zero on every row). `qc_flag`: `gear_count_from_interviews` (20 rows, Feb 3 to 13, 2024 and three later 2023-24 dock rows: during the L&I PFD stand-down the samplers could not walk the floats and recorded the day's TOTAL gear from interviews as the count, a day's deployments rather than a snapshot; the reader holds them out via `run_config$effort_qc_drop`), `missing_count_time` (30 rows; the reader drops these anyway), `implausible_count_time` (3 rows with a clock time before 05:00 on a real count; informational, kept).
- **Shifts** (`build_sampler_shifts.R`). As on 2026-09-09 (11 rows flagged and held out of the hours), plus the sampler's on-site conditions per survey and the survey-level holiday flag. Grays Harbor shift medians: 3.5 h (2022-23), 4.1 h (2023-24), 6.0 h (2024-25 and 2025-26).
- **Vessel tally** (`build_comm_charter_tally.R`). 2024-25 from the `wes commercial tally` sheet (identical to the previous workbook); 2025-26 from the same sheet reconciled against the survey sheet's per-day tallies (23 days, no disagreement). Read by header name: the column order differs between the two seasons' sheets. No tally exists before 2024-25.
- **Charter roster** (`build_charter_trips.R`). The operators' per-trip roster, and since 2026-09-11 the FRAME the charter component is expanded over (`estimate_comm_charter.R`): the charter vessels are not 100% sampled, so their catch is `N x` (mean per interviewed trip) with a finite-population-corrected variance, where `N` is the roster's sailed trips unioned per day with the tally's charter column. On 2024-25, 34 trips with 20 interviewed; 8 of the 31 sailed Westport trips fell on days without a tally.
- **Holidays** (`build_crabbing_holidays.R`). The 2024-25 named holidays (the list that had been hard-coded) applied by rule to 2022-23 through 2026-27, plus the federal observed day when a fixed-date holiday falls on a weekend. **2026-09-11: Thanksgiving Day, Veterans Day (observed) and Juneteenth were added** (69 rows), on the samplers' own Holiday? flag and the Float 20 gear count against the same month's weekday mean (2.4x, 2.3x, 1.7-2.3x); three days are re-typed per season. Christmas Eve, Presidents Day and MLK Day stay out because their counts do not support it (1.1x/0.8x, 0.8x, 1.3x). The builder prints the sampler-flagged dates the rule still does not cover. Adding a name to the rule is the whole change; note that in the PE an unsampled holiday can land in an empty (week x day-type) stratum and be expanded at zero effort (CHANGE_REGISTER D19), while the BSS gives it the weekend and holiday effort effects.

**The I/E workbook.** Maintained from the I/E database export rather than the season workbooks. The copy in the repository (7,190 interval rows through 2026-08-28, with the `time` column) is newer than the last export supplied (2026-07-23) and identical to it on every shared interval; the export also carries per-interval tide height, sea state, vessel restrictions and the razor-dig calendar, which are not in the trimmed workbook. When a newer export arrives, place it in `raw/` and regenerate the trimmed columns from it (the trimming rule is the column list above; a builder was not written because the repository copy was ahead of the export).

## The other information the season workbooks carry (reviewed 2026-09-10)

Fields judged useful and now carried, each with the modelling use it is kept for: `bay_or_ocean` / `river_or_ocean` (where the boat fished: Inside Bay against Ocean north or south of Point Chehalis; the basis for a bay-versus-ocean apportionment of the Westport boat catch, which the management areas need and the model does not yet do), `boat_name` (per-vessel catch means for the census, and the link between a roster trip and its interview), `total_vehicles` (vehicles per boat party, the trailer-to-boat conversion check), the released-crab fields (discards, for a total-catch or handling-mortality extension), the on-site conditions per survey (`special_conditions` carries "Small Craft Advisory", "Bar Restrictions", "Halibut Opener", "Razor Clam Opener": the boat-effort covariate candidates nearest to what a skipper saw at the bar that morning; `run_weather` fetches modelled weather from external APIs instead), `crabber_count` and `jetty_people_count` (a people-based shore effort measure beside the gear count; the model uses gear), `buoy_count` (2022-24 only). Reviewed and not carried: the notes columns (free text with vehicle and personal descriptions; in `raw/`), the summary and pivot tabs (derived), the `location_key` and `gear_key` tabs (encoded in the builders).

## Season columns (fishery season)

Every workbook carries a `season` column holding the **fishery season** label (`2024-25` = the window Sep 16, 2024 through Sep 15, 2025), not a calendar season. For the multi-year files (`ingress_egress`, `fishery_opener_dates`) the label is derived per row from the date, using a Sep 16 boundary (a date on or after Sep 16 of year Y is season `Y-(Y+1)`). This replaces the old `ingress_egress` `season` column, which held a calendar season (`Fall`/`Winter`/`Spring`/`Summer`) that no code used.

Which readers filter on it:

- `effort_combined.xlsx` and `interview_combined.xlsx` filter to `season == run_config$season_filter` (existing behavior).
- `wes_commercial_tally.xlsx` carries the column but is scoped by the census date window in `estimate_comm_charter` (unchanged); the column is provenance.
- `fishery_opener_dates.xlsx` carries the column; the spillover diagnostic joins by date, so all rows are kept (a lookup calendar).
- `ingress_egress.xlsx` carries the column but is **not** filtered by default: the `L_effective` day-length regression intentionally pools all seasons of I/E history. Set `run_config$ie_filter_by_season = TRUE` to restrict it to the current season.

## Columns: modelling-relevant

The 2026-07-16 trim kept only the columns the pipeline used; the 2026-09-10 rebuild reinstated the fields with a modelling use listed above (the effort vehicle/buoy/crabber/jetty counts, the interview fishing area, boat name, vehicles and released-crab fields, the tally `*_interviewed` columns and notes). Still out: the interview and effort `notes` (in `raw/`) and the `ingress_egress` weather/metadata columns (the weather module fetches tide/weather from external APIs, not from this file). The `ingress_egress` file still carries `crabbers_on`, `crabbers_off`, and `boats_out` (the raw ingress/egress survey tallies), though only `crabber_flow` (shore) and `boats_in` (boat) reach a model. A new `boats_crabbing` / `boats_total` classification pair (keys `ie_crab_col` / `ie_total_col`) is being added to `ingress_egress.xlsx` to update the crabbing fraction f once the WBL egress pilot lands.

## Input options in run_config

Input selection is surfaced in `run_config.R` so a different port, site set, or workbook can be run without editing the readers:

- Filenames: `effort_file`, `interview_file`, `tally_file`, `input_sheet`; `ie_data_file` / `ie_sheet`; `crabbing_holidays_file` / `crabbing_holidays_sheet`; `fishery_opener_dates_file` / `fishery_opener_sheet`; `sampler_shifts_file` / `sampler_shifts_sheet` (2026-09-09); `charter_trips_file` / `charter_trips_sheet` / `charter_roster_port` and `charter_frame` (2026-09-10); `effort_qc_drop` (2026-09-10).
- The crabbing-fraction classification: `crab_fraction_contact_areas` (NULL = `boat_launch_areas`; `"all"` for every private-boat interview) and `crab_fraction_source` (2026-09-09).
- Row/site selection: `gh_creel_location` (interview), `gh_effort_areas` (effort site whitelist), `shore_dock_float20` / `shore_dock_float17` (the paired gear-count floats), `boat_launch_areas` (trailer-count sites), and `ie_shore_location` / `ie_boat_location` (the I/E `location_name` series).

Each reader uses the config value with the historical Grays Harbor / Westport value as a fallback, so a run works even if a key is not set.

## Notes on the workbook format

- **Dates are ISO text.** Each `date` column stores `yyyy-mm-dd` as text (not an Excel date cell) so `as.Date()` parses it identically in any timezone. Keep that format on re-export. This also resolves a prior defect where `effort_combined.csv` and `fishery_opener_dates.csv` had been re-exported as `M/D/YYYY`, which their `as.Date(date)` readers would have read as `NA`.
- **Sheet name.** Every workbook uses a single sheet named `data` (override per file via the sheet params above).
- **Interview gear column.** `number_of_gear` is the intended gear count (historically column N in the raw iForm export); keep the header name intact on regeneration.
- **Interview row filters.** The readers drop non-crabbing rows (`number_of_gear == 0`, under any trip-completion status; an NA gear count is kept) and gear-tampered rows (`gear_tampered == 1`, populated since 2026-09-09). Keep the `completed_trip` and `gear_tampered` columns on regeneration; the builder does.
- **Effort row filters.** Rows whose `qc_flag` is in `run_config$effort_qc_drop` are held out (default `gear_count_from_interviews`; `"none"` keeps every row); rows without a count time are dropped as before.
- **Boat-type typo.** The source spells the commercial category "Commerical" (one 'm'); the prep matches it by regex, so do not "correct" it without updating the matcher.

## Regenerating an input

Run `Rscript 04_input_files/build_all_inputs.R` from the repository root (or the one builder concerned). Each builder keeps the exact column names, the `data` sheet, ISO-text dates and the `season` column, prints its report and a comparison with the workbook it replaces, and never edits the source workbook in `raw/`. Adding extra columns is harmless (readers reference columns by name).
